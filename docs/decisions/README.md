# Architecture Decision Records

ADR фиксирует значимое решение о **продуктовом обещании, архитектуре, контракте
или технологии** вместе с контекстом и последствиями.

**Процессное решение ADR не оформляется.** Темп разработки, глубина review,
параллелизм и порядок работы записываются в раздел «Темп разработки» «Правил
движения» [`ROADMAP.md`](../product/ROADMAP.md). Правило принято владельцем
2026-07-31: за четыре дня было принято семь ADR, из них три процессных, а
процессное правило пересматривается чаще архитектурного — там его пересмотр
стоит правки абзаца, здесь стоил бы нового ADR. Уже принятые процессные ADR
([0014](0014-parallel-agents-and-autonomy.md),
[0017](0017-raise-parallel-writing-ceiling.md)) продолжают действовать; там, где
«Правила движения» расходятся с их буквой, расхождение названо в тексте
конкретного правила.

## Статусы

- `Proposed` — решение обсуждается.
- `Accepted` — решение действует.
- `Superseded` — решение заменено новым ADR.
- `Rejected` — вариант рассмотрен и отклонён.

## Правила

- Имя файла: `NNNN-short-kebab-case-title.md`.
- Номер не переиспользуется.
- Принятый ADR не переписывается так, чтобы исчезла история выбора.
- Новое решение ссылается на заменённое.
- Детали реализации остаются в профильной документации; ADR хранит сам выбор и
  его причины.
