# Architecture Decision Records

ADR фиксирует решение, которое дорого откатить: движок, стек, граница слоёв,
ключевой игровой контракт. Всё остальное — короткий раздел в `docs/design/`
или описание PR.

## Статусы

- `Proposed` — обсуждается.
- `Accepted` — действует.
- `Superseded` — заменено новым ADR.
- `Rejected` — рассмотрено и отклонено.

## Правила

- Имя файла: `NNNN-short-kebab-case-title.md`, номер не переиспользуется.
- Принятый ADR не переписывается так, чтобы исчезла история выбора. Новое
  решение ссылается на заменённое.
