# ADR 0001: Память проекта в Git и Markdown

- Статус: Accepted
- Дата: 2026-07-26
- Ответственные: владелец проекта и агенты разработки

## Контекст

Проект будет разрабатываться преимущественно агентами. Контекст отдельного чата
ограничен, а реализацию продолжат разные исполнители. Нужна долговременная,
версионируемая и доступная рядом с кодом память.

## Рассмотренные варианты

### Только чаты и задачи

Начать легко, но решения теряют контекст, противоречат друг другу и плохо
связываются с фактической версией кода.

### Внешняя wiki как основной источник

Удобна для чтения, но документация может разойтись с веткой кода и требует
отдельной интеграции для каждого агента.

### Markdown рядом с кодом

Документы проходят тот же review и сохраняют ту же историю, что и код. Их можно
читать локально без дополнительного сервиса.

## Решение

Git-репозиторий является канонической памятью проекта:

- актуальные знания хранятся в Markdown рядом с кодом;
- значимые решения оформляются ADR;
- задачи и критерии готовности после публикации репозитория ведутся в GitHub
  Issues;
- порядок работ отображается в GitHub Project;
- изменения проходят через небольшие Pull Request;
- чат используется для исследования и обсуждения, но итог переносится в
  репозиторий.

## Последствия

- Изменение системы часто требует изменения документации в том же PR.
- Агент перед работой обязан прочитать относящиеся к задаче документы.
- Документация может быть перенесена в другой интерфейс для чтения, но Markdown
  в Git остаётся источником истины.

## Проверка решения

После первых трёх вертикальных срезов проверить:

- способен ли новый агент продолжить задачу без пересказа истории чатов;
- находятся ли причины ключевых решений по ссылкам из Issue и PR;
- соответствует ли документация текущему поведению сборки.
