# Спека: панель управления на иконках и выделение мышью

Статус: принята владельцем 2026-07-28  
Источник: owner playtest после Issue #48, команда `ADJUST`

## Зачем

Owner playtest функциональной комнаты дал `ADJUST` с двумя пунктами: «очень
неудобно копать кнопками, сделать нормальное управление мышкой» и «визуал комнат
как-то выделить».

Эта спека закрывает **первый пункт**. Второй требует реализации
[ADR 0008](../decisions/0008-three-quarter-projection.md) и живёт в
[Issue #52](https://github.com/anshushunov/dungeon-fortress/issues/52).

Текущее состояние интерфейса: текст везде. Шапка, две полосы текстовых кнопок,
ростер, инспектор, лента событий и легенда из восьми строк прозы, объясняющая,
что значат цветные квадраты. Все кисти работают поклеточно — карман 4×3 стоит
двенадцати кликов. Для игры, где разметка пространства и есть единственный способ
выразить намерение, это главный источник трения в минутном цикле.

Жанр решил это одинаково: прямоугольное выделение перетаскиванием. Dwarf
Fortress, RimWorld, Prison Architect, Oxygen Not Included — везде «зажал,
потянул, отпустил» с превью области.

## Границы решения

Спека меняет **слой ввода и представления**. Симуляция, контракт, tuning, схема
канонического снапшота и словарь команд не затрагиваются.

Словарь уже готов: `dig_designate`, `zone_paint`, `build_designate` принимают
**список клеток**, а не одну. Прямоугольник схлопывается в один атомарный command
с массивом `tiles`, поэтому ADR не требуется.

## Разбиение на задачи

Три единицы работы с разными исполнителями.

| Задача | Исполнитель | Выход |
|---|---|---|
| **A. Генерация иконок** | Codex | `src/DungeonFortress.Game/assets/icons/*.png` по манифесту плюс `docs/art/icons-v1-provenance.md` |
| **B. Панель на Control-узлах** | implementation-агент | обе полосы кнопок на `Button` с иконкой, подсказкой и `toggle_mode` |
| **C. Прямоугольное выделение** | тот же агент, что B | протяжка для всех кистей с превью и отменой |

B и C правят один файл и один слой ввода — их делает **один агент одной
задачей**, иначе они подерутся за маршрутизацию кликов. A идёт параллельно:
файлы не пересекаются вообще.

Зависимость снимается манифестом: до появления реальных PNG кнопка рисуется
заглушкой, подмена файлов не требует правок кода.

Генерацию изображений выполняет Codex — см.
[`ANIMATION_PIPELINE.md`](../art/ANIMATION_PIPELINE.md). Без provenance ассет не
принимается.

## Задача A — манифест иконок

**Размер.** Генерация 48×48, отрисовка 24×24 — ровно 2×, чистое уменьшение. Это
прямой урок предыдущего пака: goblin-спрайты 96×96 рисуются в 20×20, даунсемпл
96 → 20 без mipmap, и вся работа генерации уходит в кашу. Кратный размер эту
ошибку исключает.

**Формат.** PNG с альфой, без запечённого фона, без текста внутри изображения.

**Главное ограничение промпта:** иконка обязана читаться **силуэтом на 24
пикселях**. Мелкая детализация на этом размере не «необязательна», а вредна.

Шестнадцать файлов.

| Файл | Что изображает |
|---|---|
| `icon_inspect.png` | осмотр клетки или существа |
| `icon_paint.png` | кисть — закрасить зону |
| `icon_erase.png` | ластик — стереть зону |
| `icon_dig.png` | кирка — обозначить породу под копку |
| `icon_dig_cancel.png` | кирка перечёркнута — снять разметку копки |
| `icon_stockpile.png` | склад материалов |
| `icon_build.png` | чертёж постройки |
| `icon_build_cancel.png` | чертёж перечёркнут — снять blueprint |
| `icon_zone.png` | выбранный вид зоны (селектор) |
| `icon_priority.png` | приоритет вида работ (селектор) |
| `icon_rule.png` | правило владения (селектор) |
| `icon_play.png` | пуск времени |
| `icon_pause.png` | пауза |
| `icon_step.png` | один тик |
| `icon_food.png` | готовая еда |
| `icon_stone.png` | камень |

Сырьё, «выкопано» и «разметка» в шапке остаются числами с коротким словом:
для них нет узнаваемого силуэта на 24 px, и попытка его придумать даст пятно,
которое придётся объяснять подсказкой. Иконка, требующая подписи, хуже подписи.

Скорости `0.5x / 1x / 4x / 16x` и `BASE / NEGLECT` **остаются текстом**. Цифры и
так универсальны, а фикстуры — отладочная возможность, а не игровое действие;
иконки для них были бы тратой генерации.

### Три кнопки — не кнопки, а селекторы

`zone <вид> [Z]`, `job <вид> <приоритет> [J]` и `<правило> <значение> [K]`
**показывают текущее значение** и переключают его по клику. Иконкой они не
заменяются: иконка сообщает, что это за элемент, но не какое у него значение
сейчас.

Форма для них — **иконка плюс текущее значение текстом**, поведение по клику
прежнее: циклический перебор. Это единственные три элемента полосы, где текст
остаётся на экране постоянно, и остаётся осознанно.

## Задача B — панель на Control-узлах

Сейчас обе полосы рисуются через `DrawRect` и `DrawString` в `_Draw()`, а
попадание клика проверяется вручную по прямоугольникам из `ControlButtons()`.

Кнопки переезжают на `Button` с `icon`, `tooltip_text` и `toggle_mode`. Ручное
сопоставление «нарисованный прямоугольник ↔ зона клика» удаляется: это источник
дефектов по построению, и удалить его лучше, чем обвесить иконками.

**Каждая кнопка объясняет себя** иконкой, бейджем горячей клавиши в углу и
всплывающей подсказкой с названием и коротким описанием при наведении. Так
сделано в RimWorld и Prison Architect. Десяток незнакомых символов без подписи
были бы **менее** дружелюбны, чем текст.

Полос две. Верхняя — время: пуск/пауза и шаг иконками, скорости и фикстуры
текстом. Нижняя — кисти: восемь действий иконками и три селектора вида
«иконка + значение».

**Тексты подсказок живут в `DungeonFortress.Presentation`**, не в `Main.cs`: это
текст, по которому игрок учится игре, и по
[ADR 0011](../decisions/0011-presentation-layer-without-engine.md) он обязан быть
юнит-тестируемым без запуска движка.

### Маршрутизация ввода

Карта **не** становится Control. Её обработка переезжает в `_UnhandledInput`.
Godot отдаёт клик сначала Control-узлам, и до карты доходит только
необработанный. Владение кликом определяется деревом узлов, а не арифметикой по
координатам, поэтому дефект «клик по кнопке провалился на карту» становится
невыразимым.

## Задача C — прямоугольное выделение

- зажатие ЛКМ начинает область, перетаскивание обновляет превью;
- во время протяжки видно подсвеченную область и **число клеток**, на которые
  подействует команда;
- отпускание применяет кисть **одной атомарной командой** со списком тайлов;
- `Esc` или ПКМ во время протяжки отменяет, не оставляя следа в журнале;
- одиночный клик остаётся прямоугольником 1×1.

Кисти имеют `toggle_mode` и остаются активными. `Esc` при активной протяжке
отменяет протяжку; `Esc` без протяжки снимает кисть.

## Проверяемость без чтения пикселей

Три механизма, все в духе Issue #28: текст остаётся источником истины для
проверок, даже когда перестаёт быть источником истины для глаз.

**`ui.controls` в структурном выводе** — список
`{id, label, hotkey, tooltip, active, enabled}`. «Какие кисти доступны и что они
делают» становится обычным юнит-тестом в `DungeonFortress.Presentation`, то есть
проверяется в CI на каждом pull request.

**Тест целостности манифеста** — у каждого control-id есть файл иконки, и на
каждый файл кто-то ссылается. Ловит обе тихие поломки: сгенерировали иконку,
которую никто не использует, и подключили кнопку без иконки. Этот класс дефекта
не виден в диффе.

**`ui.summary` остаётся семантическим дампом.** В структурный вывод по-прежнему
уходит `food 14+2 • raw 24+6 • stone 4L 0C 0/0S`, даже когда на экране это
иконки с числами. Поэтому `tests/golden/ui/*.json` **не регенерируются**, а
golden-тесты продолжают проверять смысл шапки.

**Выделение проверяется журналом команд, а не картинкой:** протяжка по области
из N клеток порождает ровно одну команду с N тайлами, отменённая протяжка — ноль
команд. Частично применённой разметки не существует по построению.

## Критерии готовности

- карман 4×3 размечается одним движением, а не двенадцатью кликами;
- во время протяжки видно область и число клеток;
- отменённая протяжка не оставляет записи в журнале команд;
- прямоугольник применяется одной атомарной командой;
- каждая кнопка имеет иконку, бейдж горячей клавиши и подсказку;
- `ui.controls` присутствует в структурном выводе и покрыт тестами;
- тест целостности манифеста зелёный;
- **полоса кистей помещается в ширину карты.** Карта — 28 × 22 px = **616 px**;
  полоса кистей сейчас кончается на 676 px, то есть шире карты, что и
  зафиксировано в ограничениях PR #50. Восемь иконок по 28 px плюс три селектора
  «иконка + значение» укладываются примерно в 460 px. Если после перехода полоса
  не стала уже 616 px, что-то сделано не так;
- `tests/golden/ui/*.json` проходят **без регенерации**;
- `scripts/verify.ps1` зелёный.

## Что не входит

- реализация ADR 0008: тайлы карты, фасады стен, Y-sort, размер тайла, камера;
- визуал помещений, границы зон и легенда — [Issue #52](https://github.com/anshushunov/dungeon-fortress/issues/52);
- спрайты существ и иконки-мысли над головами;
- тексты инспектора, ленты событий и ростера;
- новые кисти и типы зон;
- локализация;
- выбор палитры и art direction — отдельный gate.

## Риски

**Читаемость иконки на 24 пикселях проверяется только глазом.** Ни один
автотест этого не поймает: он подтвердит, что файл на месте и подключён, но не
что кирка похожа на кирку. Это единственный критерий, принимаемый на playtest, и
вероятная причина второй итерации генерации. Манифест делает её дешёвой —
меняются файлы, код не трогается.

**Регрессия ввода.** Переразводка кликов затрагивает всё взаимодействие с
картой. Прикрыто тем, что `verify.ps1` уже гоняет controls smoke через реальный
путь кистей, включая постройку поста.

**Блок не закрывает второй пункт `ADJUST`.** Легенда, зоны и плоские квадраты
остаются. Ожидать от следующего playtest читаемой карты не следует.
